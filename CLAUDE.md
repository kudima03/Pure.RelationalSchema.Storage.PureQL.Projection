# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

All `dotnet` commands must be run from the `./src` directory.

```bash
dotnet restore
dotnet build --no-restore -warnaserror
dotnet format --verify-no-changes             # check code style (CI enforces this)
dotnet format                                  # auto-fix code style
dotnet test --no-build --verbosity normal      # run xUnit tests
dotnet pack --configuration Release -p:Version=<version> --output .
```

CI additionally passes `-p:AssemblyVersion` (pinned to the major) and `-p:FileVersion`; see `.github/workflows/publish-nuget.yml`.

Mutation testing (currently disabled in CI; slow locally):

```bash
dotnet tool install -g dotnet-stryker
dotnet stryker --mutation-level Complete --break-at 48
```

## Architecture

`PureQLProjection` is the public entry point — a `sealed record` that implements `IStoredTableDataSet`, `IAsyncEnumerable<IRow>`, and `IQueryable<IRow>`; the other public types are `QueryExecution` and `PureQLFilteredSchemaDataSet` (a schema dataset whose tables are filtered by PureQL conditions, see below). Its constructor takes an `IEnumerable<IStoredSchemaDataSet>` (the data source), a `PureQLQuery` (or a subquery-less `Query`) and optionally the parameters' values (`IReadOnlyDictionary<string, IParameter>`) from `PureQL.CSharp.Model` `0.1.0-preview.15.0.0`, which is generated from PureQL specification `0.1.0-preview.3.0.0`; the interpreter implements that specification, its **Semantics** exactly (the specification's `README.md` is the reference for every value this library computes). The query is validated and **compiled to one LINQ expression tree** when the projection is built; `Expression` is that tree. **The library is the medium between PureQL and a translating LINQ provider**: enumerating the projection hands the query below the result rows to the provider of the stored tables it reads (`Pure.RelationalSchema.Storage.PostgreSQL.Querying` translates it to one SQL statement), maps its values to result rows, and runs the tree in memory only when the tables are held in memory (`EnumerableQuery` provider) or the provider refuses the query with `NotSupportedException` before its first value; `Execution` / `FallbackReason` say which happened (issue #237).

The tree may hold only what a SQL provider can translate: `Queryable` operators (`Enumerable` ones only over a group, a window's rows or a list), BCL value-type/string/`Math` members, the public functions and query operators of this library (`PureQLMath`, `PureQLText`, `PureQLTime`, `PureQLConversions`, `PureQLAggregates`, `PureQLWindows`, `PureQLRecursion`: what an operator is where the BCL has no member that computes exactly what the specification defines; a provider translates a call by its method or refuses the tree), value tuples, constants and captured parameters — no compiled delegates, invocations or client-side `AsEnumerable`/`ToList`. **The tree of a construct that existed in specification 2.0.1 must keep its shape** (`Tree/ExpressionTreeTests` holds them), so a provider that translated it still does; exactness in memory is added by `ExactArithmetic` on the copy that runs, never by changing those shapes. The result rows (`ResultRow`) are built only by the last `Select`, which is never simplified into the query and only maps a tuple's items. `Tree/TranslatableTreeTests` enforces this over the whole sample catalogue.

Values in the tree: integer `long?`, decimal `decimal?`, string `string`, boolean `bool?`, date `DateOnly?`, time `TimeOnly?`, datetime `DateTime?` (a UTC instant), uuid `Guid?`. Null semantics are C#'s nullable semantics, which match the spec, except `>=` / `<=` of two nulls (true in the spec: `Comparison` adds `|| (a == null && b == null)`). **Never use binary floating point**, also not at build time: a decimal result is exact, rounded once half away from zero to 28 digits (`Exact`).

- **Query shape** — `QueryProgram` (main query + named subqueries). A query is a `QueryShape`: `QueryClauses` (plain, grouped, total, or the `next` of a recursion; a total query's `aggregate` columns become `Select`) or `CombinedQuery` (a `SetOperation` over shapes). A subquery is a `NamedQuery` with a `SubqueryBody`: `PlainSubquery`, `InlineRows` or `RecursiveQuery` (seed, next, maxDepth). The model has one record per variant of a query (with/without pagination, orderBy, main or not), all with the same property names, so shapes are read by property (`ModelNode`), not by type. `Source`, `JoinClause`, `TypedExpression` (select / aggregate column, group key or inline cell, each with its alias and the type its expression declares) and `OrderKey` (an expression, or the alias of a select column: `QueryClauses.Sorted`) are its parts; `Headers` gives the columns (`QueryColumn`) of a shape or a subquery, merging the inputs of a set operation and the rows of an inline subquery into the least types (`DeclaredType`) or throwing `ArgumentException`
- **`ModelNode`** — structural access to model nodes: unwraps C# unions (`IUnion.Value`), reads operands by property name (`Child`, `Optional`, `Children`), and walks a tree (`Nodes`) for validation and analysis. Never pattern-match a union type against itself; unwrap and match the record
- **`DocumentTree`** — the tree of a document: the main query plus the `ResultRow` materializing `Select`; builds each subquery where it is read, per `QueryUse` (rows / aggregated / membership), and inlines it. A combined query is its inputs, each `Shaped` into the operation's columns, folded with `Concat` / `Union` / `Intersect` / `Except`; inline rows are `oneRow.SelectMany(one => new[] { (cells), ... })`; a recursive subquery is `PureQLRecursion.Recursive(seed, level => next, maxDepth)`, `next` built while the subquery's own name stands for the `level` parameter (`_levels`)
- **`QueryTree`** — the tree of one query, in spec order: per-source scans (`SourceScan`: `Constant(dataset).Select(row => (fields))`, or `Constant(origin).Where(row => condition).Select(row => (fields))` for a `FilteredTable`, only the fields read; `StoredColumn` is the cell read: `IsNullOrEmpty(text) ? null : Parse(text)` for a field the query declares nullable, the bare `Parse(text)` for one it declares non-null in a reference where its source has a row of its own and nullable in none (`Required`), so a provider sees a non-null key and SQL joins with `=`, a hash/merge join, instead of `IS NOT DISTINCT FROM`, a nested loop — issue #243; an empty cell under a non-null declaration fails the parse) → where conditions split and pushed to sources/joins unless an outer join makes the source optional → joins → rest of where → plain (window passes, see below) / grouped (`GroupBy`, having) / total (one-row constant source) projection with orderBy → distinctBy → pagination. A window function of a plain query (`Windows.IsFunction`: an aggregate whose `over` is a window, a ranking function, `previous` / `next`), found in `select` and `orderBy`, is computed by one pass each over the rows before they are ordered (`Windowed`, `Pass`): `PureQLWindows.Over(rows, partitionBy, orderBy, peers, frame, window => (window.Row, value))`, so after n passes a row is `(...((row, v1), v2)..., vn)`; the select's `Scope` reads the values there (`computed`) and the query's own row through the first items. A join is a hash join when an and-ed condition of `on` (or a where condition moved into an inner join) equates an expression over the rows so far with one over the joined source (`KeySides`): `Join` on the tuple of keys (+ `Where` for the other conditions) for inner, `GroupJoin` + `SelectMany(DefaultIfEmpty)` for left/right (the other conditions filter the matches), full = left join `Concat` the joined rows whose group is empty; a tuple key is never null, so null keys match as `=` says. A nullable key side that `on` or `where` guards with `notEqual(side, null)` is compiled as `side ?? default` (`Key`), so a provider compares it with `=` instead of `IS NOT DISTINCT FROM` and PostgreSQL hashes the join; the guard drops the rows with a null key, so the pairs the default makes are dropped too (issue #249). Without a key it is the correlated `SelectMany` nested loop (`NestedLoopJoin`). Drops repeated/row-independent order keys, distinctBy over all group keys, and ordering of subqueries read only by `in` or by aggregates. Rows are value tuples (`Tuples`); the query's rows (`AllRows`) are one shared subtree that aggregates over all rows read
- **`Scope`** — what an expression compiles against: a row expression (row context), a row plus all rows (projection), all rows (total), or a group parameter (group); while a window function is computed, a `RowSet` (the window's rows, their element type, the row scope of one of them, the window) replaces the rows aggregates fold, and in the select of a windowed query `computed` maps each window function node to where its value is read. Compiles fields, keys, literals, parameters (`ParameterValues.Value`: a captured `QueryParameter<T>.Value`, the bound value, or `NotSupportedException` when read unbound) and operators
- **`Operator`** — dispatch. The model names every operator record after its operator, operand family where signatures differ, declared type and context (`AddIntegerRow`, `YearDatetimeIntegerNullableRow`, `SumDecimalGroup`, …), and an operator names its operands the same way in every signature, so the longest operator name a record's type name starts with selects the compiler (`Operator.Name`); the compiler reads the node's declared type (`IOperator.Type`) and its operands' CLR types where signatures differ. Adding an operator: one entry in `Operator.All`, one method in its family
- **Operator families** — `Arithmetic` (numbers; a list is a left fold typed step by step), `Text` (strings, regex), `Temporal` (dates, times, zones: `Zoned` lifts over the zone too), `Conversions`, `Logic` (incl. `greatest` / `least`, `nullIfEqual`), `Comparison` (incl. `in`; strings via `string.CompareOrdinal`), `Aggregates` (`StringComparer.Ordinal` for string min/max; `first` / `last` / `concatAll` through `Ordering`; statistics through `PureQLAggregates`), `Windows` (ranking, `previous` / `next`, frames) each return an `Expression`; `Lifted` builds null-propagating operations, `Typed` the typing/coercion helpers, `Lists` the list operand of `in`, `Literals` literal constants, `Linq` the `Queryable`/`Enumerable` calls (and the counterpart over plain sequences of a query operator, also of this library's), `Functions` calls of static methods by argument types, `Ordering` the `OrderBy`/`ThenBy` chain of a query, a window and an aggregate
- **Function libraries** (public, pure, non-null in and out unless a `TryAs…`): `PureQLMath` (+ `FixedPoint`: correctly rounded powers, logarithms and trigonometry in big-integer arithmetic), `PureQLText` (+ `Utf16`, `CaseMapping` with the generated `UnicodeCaseData`, `RegexTranslation` / `RegexDialect` / `CodePointSet`: the regex dialect as a .NET pattern that matches by code point), `PureQLTime` (+ `ZoneClock`, the generated `TimeZoneNames`), `PureQLConversions`, `PureQLAggregates` (+ `ExactSum`, `ExactMoments`, `ExactPairMoments`, `Percentiles`, `TemporalUnits`); `Exact` is the shared decimal core (a ratio of big integers rounded once). `PureQLWindows` / `PureQLWindow<TRow>` / `PureQLFrame` / `PureQLRangeUnit` and `PureQLRecursion` are the query operators, each in a `Queryable` form (what the tree holds) and an `Enumerable` form (what computes it). Called as code, a `Queryable` form computes over an `EnumerableQuery` and refuses any other provider but `ProjectionProvider` with `NotSupportedException` (`Linq.Composable`): `Pure.RelationalSchema.Storage.PostgreSQL.Querying` evaluates a closed call that returns a query while it reads a tree, and building the query with its provider would hand it the same node back forever (a hang, then a stack overflow). `PureQLRecursion` has a third form, over a plain sequence with an `IQueryable` `next`, which LINQ to Objects' `EnumerableRewriter` picks when an `EnumerableQuery` runs the tree as it is The generated files and the test vectors come from the scripts in `tools/` (Python; each says how to run it): never edit generated data by hand
- **`ExactArithmetic`** — the visitor that makes a tree compute as the specification defines when it runs here: a decimal `+ - * /` → `PureQLMath`, `Math.Round(a / b)` → `PureQLMath.RoundQuotient`, `(decimal)Math.Pow(10, n)` → `PureQLMath.PowerOfTen`, integer `%` → `PureQLMath.Modulo`, `Enumerable.Sum` / `Average` → `PureQLAggregates`. `LocalProvider`'s rewriter derives from it and `Simplifier.Fold` applies it, so a folded constant is exact too
- **`Simplifier`** — build-time optimizer (bottom up): constant folding (a failing fold is kept; two constant strings fold through `CodePoints`, not UTF-16 ordinal; decimals fold through `ExactArithmetic`; a conversion to `double` and `Math.Pow` are never folded, and `Math.Round` of a constant quotient folds in one rounding), boolean simplification, null/unlifting rules, tuple member-of-new, `Where` merge, `Where`-below-`Select` (uncorrelated only), `Select` fusion, identity `Select` removal, `Select` below `Skip`/`Take`. A stored table's scan `Select` is never fused, so every source keeps one shape
- **`Execution`** — runs a projection's tree: splits it into the query and the `ResultRow` mapping, picks the provider (the first stored table's that is not an `EnumerableQuery`), `provider.CreateQuery(query)` enumerated with the first value read eagerly, each value mapped by the compiled mapping; `NotSupportedException` there falls back to `LocalProvider` and is kept as `FallbackReason`; any other exception propagates. **`ProjectionProvider` / `ProjectionQuery`** — the projection's `IQueryProvider`: its own tree runs through `Execution`; LINQ composed over it runs in `LocalProvider` with the tree replaced by the projection's rows
- **`LocalProvider`** — runs a tree in memory (LINQ to Objects) on a rewritten copy, compiled once per run: each stored table read once (a `Memo` constant typed `IEnumerable<IRow>`), uncorrelated queries nested in lambdas computed once into a `Memo` that is an `ICollection<T>` (so `Enumerable.Contains`, i.e. `in` over a subquery, is a hash-set lookup), every query operator (`Linq.IsQueryOperator`: `Queryable`'s, `PureQLWindows.Over`, `PureQLRecursion.Recursive`) whose source became a plain sequence turned into its counterpart over one (`Linq.OverEnumerable`; the lambda of a recursion's `next` gets a plain-sequence parameter, `Level`; a `Queryable` call over an `EnumerableQuery` constant would be re-executed, rewritten and compiled, for every row that reads it), `CompareOrdinal`/`StringComparer.Ordinal` replaced by `CodePoints` (the spec's code-point order; UTF-16 ordinal differs only for surrogates)
- **`CellText` / `ValueTypes`** — format result cells (a decimal exactly, in the spec's spelling: no exponent, no trailing zeros in the fraction); map column types to PureQL types and CLR types, and back (`integer` → `LongColumnType`, `decimal` → this library's `DecimalColumnType`, named `decimal`, since `Pure.RelationalSchema` has no column type that holds a decimal exactly — issue #252)
- **`QueryValidator`** — the interpreter-side checks of the spec (the `## Validation` table of the specification, rows "interpreter"): entities, sources, fields and their types, outer-join nullability, group key references and aliases, unique names, `distinctBy` and `orderBy` column aliases, subquery order, set operation and inline row columns (`Headers`), the rules of a recursive subquery, one type per parameter, bound parameter types, and the values of literal-or-parameter positions (regex pattern and group, zone, fraction, offset, buckets, frame counts, range distances, maxDepth, pagination); throws `ArgumentException`
- **`PureQLFilteredSchemaDataSet`** / **`FilteredTables`** / **`FilteredTable`** — row filters below a query (Elegant-soft/Concentrator#687). The public record decorates an `IStoredSchemaDataSet` with conditions (`BooleanRow`) per table, given as `IEnumerable<KeyValuePair<ITable, BooleanRow>>` and matched by `TableHash`; its tables are a lazy hash-keyed dictionary over `FilteredTables`, which wraps each table given conditions in a `FilteredTable` per condition (no condition: the origin's table itself) and throws `ArgumentException` for a condition whose table the origin does not have, when the tables are first read. `FilteredTable` is an `IStoredTableDataSet` whose `Expression` is `origin.Expression.Where(row => condition)` and whose `Provider` is the origin's; `FilteredTable.Root`, which `QueryTree` roots every stored scan on, is `Constant(origin).Where(row => condition)` (the plain constant for any other table), so `Execution.Roots`, `LocalProvider` and a translating provider still find the origin's table as the constant, and the provider translates the `Where` at the scan. The predicate is compiled by a `Scope` with no query (`StoredColumn.Read(row, column, field.Type.Nullable)` per field, column found by field name, `IField.Source` ignored, `Typed.Test` as for `where`) after the condition is walked: a field that names no column or declares another type, a parameter, a group key or a subquery column is an `ArgumentException`. It is rebuilt, and so checked, on every read of `Expression`/`Root` and every enumeration, never when the dataset is built, so a bad condition fails only what reads its table (a projection reading it fails in its constructor). `Simplifier.IsStored` treats the `Where` over a table constant as the stored root, so the scan `Select` above it is still never fused or read through. Enumerated directly, a `FilteredTable` runs through `LocalProvider` when the origin's provider is `EnumerableQuery`, else through the origin's provider (no in-memory fallback there)
- **`Catalog`** — finds `schema.table` across all datasets; **`ResultTable`** / **`ResultRow`** — the output schema and rows

The library is **not AOT-compatible** (`IsAotCompatible = false`): operands are read by reflection and the query is an expression tree.

**Package validation:** `EnablePackageValidation = true` with `PackageValidationBaselineVersion` set in the csproj. Breaking API changes fail `dotnet pack`.

**Target framework:** net11.0 only (the model's C# 15 unions need it). `CompatibilitySuppressions.xml` records the dropped target frameworks for package validation.

**Publishing:** triggered by pushing a semver tag matching `*.*.*`. The tag value becomes the `PackageVersion`.

**CI thresholds:** code coverage warning at 99%, failure below 94%. The mutation step is commented out in `build-and-test.yml`; its threshold (48%) is unused.

**Tests:** `Api/ExecutionTests` and the provider theories of `Samples/SampleCatalogueTests` are the guard against running in memory: `Data/ProvidedTable` / `Data/RecordingProvider` fake a provider-backed table (the provider records the queries it is given and runs them with LINQ to Objects, or refuses them at a chosen stage), and the tests assert the query is handed over whole, the tables are never enumerated, and the fallback happens only on `NotSupportedException`. `Semantics/JoinTests` checks every join kind against a nested-loop oracle (null keys, repeated keys, residual conditions, integer/decimal keys, no-key fallback); `Semantics/ScaleTests` bounds the time of a join chain and an `in` over thousands of rows (a quadratic join fails them). `Samples/SampleCatalogueTests` runs every query of `PureQL.CSharp.Model.Samples` over the `Pure.RelationalSchema.Storage.Samples` fixtures and compares it with the sample's expected `Result`. `Tree/ExpressionTreeTests` asserts the tree shape with `Data/TreeText` (C#-like text; a stored cell read prints as `row[column]`, `TreeText.Full` keeps it), and `Tree/TranslatableTreeTests` checks every sample's tree with `Data/Untranslatable`. `Samples/TranslatedSampleTests` runs every sample over the fixtures stored in PostgreSQL (`Data/PostgreSqlDatabase`: Testcontainers, tables created and filled by the fixture itself, since the Creation/Insertion packages cannot store NULLs) through `Pure.RelationalSchema.Storage.PostgreSQL.Querying` and asserts `Execution == Translated`, except for the samples the provider refuses (`TranslatedSampleTests.Refused`: they must fall back with `NotSupportedException`; remove a sample from the list when the provider learns its constructs) and the one that reads no stored table (`SampleCatalogueTests.ReadingNoStoredTable`) (needs Docker; the test project references `Linq.Expressions.Translation.PostgreSql` directly to run a newer translator than the provider's dependency). `Samples/TranslatedPlanTests` reads the plans of translated queries: an aggregate over all rows in a plain select is a window aggregate, so the sources are scanned once (issue #248, fixed in the translator 0.1.0-preview.0.7.0), and a date or uuid join compares the stored columns, not their text parsed back (issue #250, fixed in the provider 0.1.0-preview.0.9.0, which reads `Parse(row.Cells[column].Value.TextValue, ...)` as the column). The filtered schema tests (`Semantics/`, `Errors/`, `Api/FilteredSchemaExecutionTests`, `Tree/FilteredSchemaTreeTests`) read the two tables and queries of `Data/Staff`; `Samples/TranslatedFilteredSchemaTests` (Docker) runs every sample over the PostgreSQL fixtures under conditions, compares it with the same filtered query run in memory, asserts `Execution` as `TranslatedSampleTests.AssertRan` does, and reads the plans to check each condition is the filter of its table's scan. A `BooleanRow` cannot hold a group key by its type, so that rejection is not tested. The other tests build their own small tables with `Data/InlineTable`. Note: `dotnet format` code fixes for IDE0010/IDE0072 ("populate switch") insert `throw new NotImplementedException()` arms — avoid partial `switch`es over `ExpressionType`.

**Parameters:** bound by name to Pure parameters (`IParameter` / `IListParameter` of `Pure.RelationalSchema.Storage.PureQL.Projection.Parameters.Abstractions`; the tests build them with `Pure.RelationalSchema.Storage.PureQL.Projection.Parameters`, or hand-made ones with `Data/TextParameter` / `Data/TextListParameter`) through the `PureQLProjection` constructors taking `IReadOnlyDictionary<string, IParameter>`. `ParameterValues` checks each one's `Type` (`Name` a PureQL type name, `Nullable` a typed null) against the query parameter's: an integer (list) binds a decimal (list), and a typed null binds only a nullable parameter. It parses `Value`, the invariant cell text, as `StoredColumn` parses a cell; a list's value is its `Items`, each checked and parsed as a scalar of the item type and copied into an array. A parameter given no value, a mismatch, text that does not parse, or a bound pagination out of range is an `ArgumentException` from `QueryValidator`, so a query with a parameter needs the constructor taking the parameters (issue #251). A `date`, `time` or `datetime` value that starts with `now` is date math (`DateMath`: `now`, then at most one `+N`/`-N` part per unit in the order `y M d h m s`, all of one sign; a date takes `y M d`, a time `h m s`, a datetime all), the format the current and offset parameters of `Pure.RelationalSchema.Storage.PureQL.Projection.Parameters` write; list items are never date math. It is checked and bound at the clock's instant when the projection is built, held by its `QueryParameter` (`Relative`), and bound again when each run starts: `Execution.Rows` reads the clock (`TimeProvider`; `TimeProvider.System` unless a constructor is given one) once, and `Relatives` swaps every `QueryParameter` constant for its value at that instant (`At`) before the tree goes to the provider or `LocalProvider`; a tree without date math is not rewritten and its runs do not read the clock. The instant is truncated to the microsecond; years and months move it by `12 * y + M` calendar months, then days, hours, minutes and seconds are added; a time adds them within a day, wrapping around midnight. `Semantics/DateMathParameterTests` (with `Data/FixedClock`) and `Errors/DateMathParameterTests` cover it. PureQL literals (`ILiteral`) appear only inside queries; `Literals` reads those.

**Known execution gaps:** stored times and datetimes are read to 100 ns; arithmetic and averages round to the microsecond, as the spec requires. A join or filter on a field declared nullable translates to `IS NOT DISTINCT FROM`, which PostgreSQL runs as a nested loop; `Samples/TranslatedJoinTests` (Docker; the fixture logs every plan with `auto_explain` and disables nested loops for the session) checks a join on non-null keys is a hash or merge join. Translated, a field declared non-null whose cell is empty is NULL and matches nothing, where the in-memory parse fails the query; a `string` field is still read as its text (`COALESCE(column, '')`).

## Code Style

Enforced by `.editorconfig` and `dotnet format --verify-no-changes` in CI:

- No `var` — always use explicit types
- No expression-bodied methods, constructors, or operators; expression-bodied properties and accessors are required
- Private fields: `_camelCase` (underscore prefix)
- File-scoped namespaces
- `using` directives outside the namespace
- Allman brace style — opening braces always on a new line
- Max line length: 90 characters
- Pattern matching preferred over `is`-with-cast and `as`-with-null-check
